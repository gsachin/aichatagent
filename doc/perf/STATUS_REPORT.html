The verdict

Measured on your own running stack a few minutes ago, the engine is doing the same work it did before — prefill and generation are unchanged to the millisecond, which is exactly what a lossless fix is supposed to look like. What the program actually removed was waste: a two-second hostname stall, a 12-second context-switch reload, a synthesiser running on the wrong processor.

But none of that survives a rebuild. .env is gitignored, and .env.example — which bootstrap_services.py and your setup docs copy verbatim onto a new machine — still says localhost and omits two keys entirely. The largest measured win in the whole program is a one-line setting that is not in the repository.

And the work that would have changed what a caller feels was never started: the two biggest levers are both blocked on a ground-truth approval that only you can give.

Fixes I confirmed working on the live process

  • Kokoro synthesis runs on CUDA. Loaded the engine in your venv: the ONNX session reports CUDAExecutionProvider active, not merely compiled in. This was the fix for a synthesiser that was silently on the CPU while the app logged otherwise.
  • Model residency is held. ollama ps reports an expiry in the year 2318 — the keep-alive is doing its job; the five-minute default would have dropped it between calls.
  • The two-second hostname stall is real and the fix works. Reproduced live: localhost costs 2,066 ms, 127.0.0.1 costs 15 ms. Ollama binds IPv4 only, and Windows burns two seconds refusing the IPv6 connection before falling back.
  • The boot gate runs and refuses to lie. Three clauses pass, the fourth fails on four config keys that are set and read by nothing, and the gate exits 2 rather than claiming readiness.

Why the improvement is not visible to you

Three causes, in order of how much each one costs you.

1 · The biggest wins are configuration, and they are not in the repository

primary cause

.env is gitignored. Four fixes the program measured and reported live only there — and .env.example, the template your own bootstrap copies onto any fresh machine, still carries the original defective values or omits the key entirely.

The voice path runs at 8192. The lead-extraction and sentiment calls use 512, 1024 and 2048. Sentiment scoring fires automatically after every conversation. So on a stack built from the template, one finished call can push the next caller's first turn into a five-to-eleven second reload — which would feel exactly like nothing was ever fixed.

There is a matching gap on the dependency side: requirements.txt declares onnxruntime-gpu==1.28.0, but the build actually running the GPU synthesis is 1.26.0. A rebuild from requirements installs a different build than the one measured.

2 · Everything that would move the felt number is blocked on you

structural

What remains is real work, not waste. Streaming generation alone is 1,202 ms of a caller sitting in silence; retrieval is another 990 ms. Both have written, self-contained stories — US-004 and US-009 — and both are marked BLOCKED on DG-03, because they change what the model returns.

Gating a behaviour-changing fix behind a quality baseline is correct engineering — you should not trade answer accuracy for speed without evidence. But the baseline needs 12 critical-intent ground truths approved by a human, and that approval is the one thing no agent can supply. It never came, so the five stories behind it never started. The program did the disciplined thing and that is precisely why it delivered so little.

This is the unblock. 137 of 161 golden-set ground truths are sitting in eval/golden_set.jsonl marked PENDING_PO_SIGNOFF. They are written; they need review, not authoring.

3 · The original target was arithmetically impossible

upstream

700 ms p50 could never be met: the endpointing silence gate alone is 600 ms — 86% of the budget — before transcription even starts. The program found this, said so plainly, and asked for a replacement SLO rather than quietly relaxing the number. That is the right behaviour, but it means the stated goal was unreachable from day one.

Worth holding onto: even with every blocked story shipped, the arithmetic lands near 2,300–2,500 ms — not 700. The honest target is a different target, and it still needs your signature.

What I would do next, in this order

  • Move the four settings into .env.example and commit them. Nothing else on this list matters until the fixes survive a fresh clone. This is minutes of work and it is the entire difference between the program having delivered and not.
  • Re-measure after that, not before. A rebuilt stack should be measured fresh — the environment as it is now is not what the docs describe, so today's numbers are not a fair baseline for either side of the comparison.
  • Approve the ground truths, or explicitly drop the quality gate. 137 cases need review. Until that is resolved, five stories — including both real levers — stay frozen. If the gate is not worth your time, say so and unblock them deliberately.
  • Decide the SLO against today's number. 4,539 ms p50 is the current truth. Pick the target you actually want, then let the backlog be ordered against it.
  • Then start US-004. Streaming generation is the single largest remaining lever and the prerequisite for streaming synthesis. It has been written and waiting since the plan was authored.
