## 5. Traps worth remembering

1. **A running app is not necessarily the current code.** A live verification failed because the app
   on `:8000` had started 9 minutes *before* the edits — an older build answered the request and
   looked like a code bug. **Always compare the process start time against the file mtimes.**
2. **`PATCH /admissions/{id}` clears a field on explicit `null`.** Send only the keys you intend to
   change; the client enforces this with an allowlist (`app/crm/status.py`).
3. **A missing record answers 500, not 404** — `NOT_FOUND` had to become a permanent-error marker
   or a write to a deleted record would retry forever.
4. **`/complete` is not idempotent** — it is sent with `is_create=True` and never retried; an
   ambiguous outcome is recorded as `unknown` for a human.
5. **The caller's number only arrives via a TwiML `<Parameter>`** — Twilio Media Streams never puts
   it in the `start` event, and the `/twilio/voice` routes are GETs (declare params as `Query`, not
   `Form`).
6. **`_publish_sentiment` must read the category from `get_lead_sentiment_category`, not from
   `get_lead`** — that query does not select the sentiment columns, which is how the first version
   pushed nothing and said nothing.
7. **`.env` is gitignored** — the CRM switches are local to this machine.
8. **The `:8098` watcher is session-scoped** — it stops when the session ends. It lives at
   `%TEMP%\crm_watch.py`; run it to watch customers, status changes and new documents live.
9. **Gates start their own uvicorn with `lifespan="off"`**, so the outbox worker does not run inside
   them — Gate 7 drives `flush_outbox` explicitly for that reason.
