# DSPMU site index — milestone 1 + prompt split

This directory is generated by `scripts/build_site_index.py` from public DSPMU
pages and PDFs. It is a **draft**: no university official has signed the facts,
and the PG admission dates come from OCR and are marked for review.

The build is deliberately outside the request path. It proves the crawl,
extraction, parser compatibility, prompt split, selective router and voice
guard. `CONTEXT_MODE=site` now selects a route-specific bundle.

## Files

| File | Purpose |
| --- | --- |
| `core_cards.md` | Stable voice/chat prefix with the university, admissions, top fees, dates, documents and contacts. Loaded first. |
| `site_map.md` | Compact prompt orientation and source notes. No 43-entry fee dump. Loaded second. |
| `recent_notices.md` | Volatile latest non-PII notices. Loaded last so a new notice changes only the tail. |
| `voice_kb.md` | Full programme/fee entity corpus for `app/kb_entities` / `VOICE_KB_PATH`. **Not loaded into the prompt.** |
| `prompt_manifest.json` | Sidecar for `ContextBundle`: fact IDs, node IDs, notice IDs, source URLs and `valid_until`. Read by `app.doc_context.document_bundle()`; not loaded into the prompt. |
| `facts.json` | Structured facts with source URLs, `valid_from`, `valid_until`, `status: draft` and `approved_by: null`. |
| `notices.jsonl` | Non-PII notice metadata. PII-heavy admission/result categories are excluded. |
| `notices.sqlite3` | Rebuildable SQLite FTS5 index over the non-PII notices. Rebuilt by `scripts/build_notice_store.py`; the router falls back to the JSONL if it is missing. An extra title guard excludes selection/student-list rows that the category filter lets through. |
| `notice_bodies/` | Optional PII-clean extracted notice text and review manifest. **Gitignored**. PII-flagged text is never written; OCR/review-needed clean text goes to `notice_bodies/_review/` and is not indexed. |
| `build_report.json` | Sources, counts, real voice/chat prompt budgets, OCR status, warnings and validation results. |
| `nodes/` | Extracted page/PDF text for auditing (no PII-category notices). |
| `cache/` | Raw public sources. **Gitignored**; regenerate rather than commit. |

## Rebuild

Offline, from the cache:

```bash
.venv/bin/python scripts/build_site_index.py
```

Rebuild only the notice search index from the committed JSONL:

```bash
.venv/bin/python scripts/build_notice_store.py
```

Install Hindi OCR data once (repo-local, gitignored):

```bash
.venv/bin/python scripts/install_hindi_ocr.py
```

Extract notice bodies offline from a local PDF directory (recommended until the
university's written permission is on file):

```bash
.venv/bin/python scripts/extract_notice_bodies.py \
  --pdf-dir /path/to/authorised/notice-pdfs --limit 5 --ocr --ocr-langs eng,hin
```

The extractor never persists PII-flagged text. OCR/review-needed text is kept
only in the gitignored `notice_bodies/_review/` directory; it is not indexed
until a human moves it to the top-level body directory. After a full extraction,
rebuild the body index with `--rebuild-db`. Live fetching is opt-in and
robots-aware:

```bash
.venv/bin/python scripts/extract_notice_bodies.py --allow-network --rebuild-db
```

Live, only after the university's written permission and with robots.txt /
content-signal review:

```bash
.venv/bin/python scripts/build_site_index.py --allow-network --verbose
```

The live fetcher uses a custom user agent with a contact address, at most one
request per second, and rejects the site's soft-404 page even when it arrives
with HTTP 200.


## Prompt split

- `DOC_PATHS` loads `core_cards.md`, `site_map.md`, `recent_notices.md` in that
  order. The first two are stable; the notice tail changes daily.
- `VOICE_KB_PATH` points at `voice_kb.md` only. `app.kb_entities` needs the full
  43-programme entity corpus; the model does not.
- `CONTEXT_MODE=site` uses `app/site_router.py`: the stable `core_cards.md`
  prefix plus the exact fee fact, about/vision/glance node, syllabus links or
  matching non-PII notices. Unknown questions fall back to the full compact
  bundle. `voice_handler` records the selected bundle as the guard evidence
  instead of re-reading the document.
- PG programme/fee/seat/eligibility questions are explicitly out of scope.
  They get a deterministic answer directing the caller to the university for
  the latest copy; PG admission dates and contact questions remain answerable
  from the core cards.
- The build measures the **real** voice prompt through
  `build_voice_system_prompt(...)` plus the question and output reserve. It
  fails if the full prompt exceeds 8,000 tokens or the document exceeds 4,000.
- Current build: document **2,461 / 4,000**; full voice **6,663 / 8,000**
  (wrapper 3,997); full chat **3,015 / 30,000**; entity corpus **3,773** tokens,
  not in the prompt.

## Source policy

- The current site's `/archive-notice` lists 4,325 rows, but its `/pdf/...`
  links return the site's 404 page on the new host. The old site's
  `News.aspx` is the working manifest and `/pdf/News/...` file server.
- The current site's fee and examination-notice HTML pages are empty shells.
  The 2026 fee, counselling and documents PDFs are linked from
  `/news/admission-merit-list`.
- The build's 4,293 rows are unique old-site PDF links after de-duplication;
  the current archive's 4,325-row count includes non-PDF rows and a different
  snapshot. The site map does not claim a total.
- Admission/selection lists and results are excluded (2,733 of the old-site
  rows in this build). The category filter is a heuristic, not a legal PII
  audit. The notice body extractor adds a conservative text scan and refuses
  to persist flagged text, but human review is still required before indexing
  a new batch.
- The 2026 fee PDF has 43 numbered programme rows. pdfplumber loses row 33
  (`Electronics`) at the page break; a text fallback recovers it, so
  `facts.json` carries 43 programmes.
- Hindi OCR uses `.tessdata/hin.traineddata` (gitignored; install with
  `scripts/install_hindi_ocr.py`). The extractor runs Tesseract LSTM mode
  (`--oem 1`) with `eng+hin` for notice bodies; the English PG admission
  notice stays on `eng`. Every OCR body is copied to the gitignored
  `notice_bodies/_review/` directory and is not indexed until a human checks it.

## Next milestone

The deterministic router is in place for fees, programme facts, about/vision/
glance nodes, syllabus links and matching non-PII notices. The FTS5 notice
store ranks title/category matches. The PDF body extractor, PII text gate and
Hindi OCR (`eng+hin`, LSTM, review-only) are implemented; the mass PDF fetch is
still waiting for written permission, and human review of OCR bodies is
pending. The remaining P1 work is the signed fact store, the golden set and
university sign-off. PG programme/fee questions are handled by the explicit
out-of-scope boundary.

This build extracts two department pages (History and the Faculty of Science)
and lists the sitemap's department pages. It does not fetch every department
page or every notice PDF; those are on-demand in the next build.
